# 모각작 데이터 수집 — 개발 요청서 (FE / BE)

**요청자:** PM (데이터)  
**목적:** 서비스에서 일어나는 행동을 빠짐없이 모아서, 대시보드·지표 목록으로 보고 싶다.  
**읽는 법:**  
- ✅ = **이미 있음** (요청 아님)  
- 🆕 = **지금 없음 → 이번에 만들어/심어 달라는 것**

---

## 0. 내가 원하는 결과 (한 줄)

> 로그를 새로 심을 때마다 내가 일일이 개발에 부탁하거나 대시보드를 새로 짜지 않아도 되게,  
> **분석용 로그를 한곳(공통)에 쌓고**, 그걸 파이프라인으로 가져와 **대시보드에 보이게** 하고 싶다.

그다음에 Notion에 “이런 이벤트 추가해줘”만 올리면, FE/BE가 그 목록만 보고 심는 구조를 원한다.

---

## 1. 지금 있는 것 / 없는 것

### ✅ 이미 있는 것 (이건 “만들어줘”가 아님)

| 구분 | 내용 |
|------|------|
| MySQL DB | 타이머 세션, 그룹 멤버십, 초대 등 **기능용 테이블** |
| 데이터 파이프라인 | 위 DB를 읽어 `data/날짜/daily_snapshot.json` 저장 (PM 쪽, 이미 동작) |
| HTML 대시보드 | DB 데이터 표시 + **GA 자리만 비워 둔 UI** (PM 쪽) |
| GA4 | 프론트에서 `sendGAEvent`로 **일부** 이벤트 전송 (timer, cheer 등) |
| Clarity | 세션 녹화 등 (별도 콘솔) |

### 🆕 지금 없는 것 (이게 요청)

| 구분 | 내용 |
|------|------|
| **공통 분석 로그 테이블** (`activity_logs` 같은 것) | 없음 |
| **공통 로그 API** (FE가 “이벤트 났다”고 치는 전용 API) | 없음 |
| **콕 찌르기 발송 DB 이력** | Redis/알림만 있고 DB에 “누가→누구에게” 없음 |
| **그룹 입장할 때마다 쌓이는 이력** | `entered_at` 마지막 시각만 덮어씀 |
| **그룹 탈퇴 이력** | 탈퇴 시 row 삭제 → 이력 사라짐 |
| **온보딩 단계별 로그** | localStorage 정도, 분석용 로그 없음 |
| **초대 링크 복사 로그** | 없음 |
| **집중 리포트 조회 로그** | 조회만 하고 기록 없음 |
| **GA4 → 우리 대시보드 연동** | GA 콘솔은 있을 수 있음. **우리 `data/ga/`로 가져오는 연동은 없음** |

## 2. 백엔드(BE)에게 요청

### 🆕 요청 B1. 공통 분석 로그 저장소 만들기

**원하는 바**  
분석용 이벤트를 **한 테이블(가칭 `activity_logs`)** 에 남길 수 있게 해 주세요.  
이벤트 종류가 늘어날 때마다 테이블을 새로 만들지 않고, `event_type` 값만 추가하는 방식이면 좋겠습니다.

**왜**  
새 로그마다 파이프라인·대시보드를 새로 짜지 않으려면, **쌓이는 곳이 하나**여야 합니다.

**완료 기준**
- [ ] 테이블(또는 동등한 저장소) 생성·배포
- [ ] FE/서버가 넣을 수 있는 **API 1개** (예: `POST /api/activity-logs`) 또는 서버에서만 insert
- [ ] staging/prod에서 테스트 이벤트 1건 조회 가능

> 상세 컬럼 초안은 `docs/activity_logging_spec.md` 참고.  
> 이름·컬럼은 팀이 더 나은 안 있으면 수정해도 됨. **“한곳에 쌓인다”만 지켜 주세요.**

---

### 🆕 요청 B2. 이미 API는 있는데 “이력”이 없는 것 — BE에서 로그 남기기

기능은 있어도 **분석용으로 안 남는** 것들입니다.  
가능하면 **B1 공통 로그에 같이** 남겨 주세요. (별도 테이블을 꼭 만들어야 하면 이유를 알려 주세요.)

| 우선 | 이벤트 | 지금 | 원하는 것 |
|------|--------|------|-----------|
| P0 | 콕 찌르기 **발송** | Redis/WS만 | 누가 → 누구, 어느 그룹, 시각 |
| P0 | 그룹방 **입장** | `entered_at` 덮어쓰기 | **입장할 때마다** 1건 |
| P0 | 그룹방 **퇴장** | 상태만 변경 | 퇴장 시각(·가능하면 체류) |
| P0 | 그룹 **가입/탈퇴** | 탈퇴 시 row 삭제 | 탈퇴해도 이력이 남음 |
| P1 | 초대 링크 **가입 성공/실패** | 부분적 | source와 함께 로그 |

**완료 기준**
- [ ] 위 P0 중 합의한 항목이 prod(또는 staging)에 기록됨
- [ ] PM이 DB 또는 API로 “어제 건수”를 셀 수 있음

---

### 🆕 요청 B3. GA4 수치를 우리 쪽으로 가져올 권한/방법

**원하는 바**  
대시보드에 **신규 사용자, 활성 사용자, 세션, 리텐션(D1/D7/D30)** 등을 넣고 싶습니다.  
GA 콘솔만이 아니라, 우리가 저장하는 형태(예: `data/ga/YYYY-MM-DD.json`)로 **매일 pull** 할 수 있게 해주세요.

**BE/인프라에 부탁할 것**
- [ ] GA4 Property ID 공유
- [ ] Data API용 서비스 계정(또는 팀에서 가능한 방식) + 읽기 권한
- [ ] (가능하면) pull 방법/예시 또는 “데이터 담당이 해도 되는지” 안내

**참고:** 실제 파이프라인 코드 연결은 PM/데이터 쪽에서 이어갈 수 있음.  
먼저 **권한과 “이 지표들을 API로 읽을 수 있는지”** 확인이 필요함.

**완료 기준**
- [ ] 서비스 계정(또는 합의된 방식)으로 하루치 지표를 읽어본 결과가 있음
- [ ] PM에게 Property ID·인증 방법 전달

## 3. 프론트엔드(FE)에게 요청

### 🆕 요청 F1. UI에서만 일어나는 행동 → 로그로 보내기

서버 API를 안 타는(또는 타도 FE가 더 정확히 아는) 행동입니다.  
**공통 로그 API(B1)가 생기면 그쪽으로**, 당분간은 팀 합의에 따라 GA와 병행해도 됩니다.  
다만 **분석에 쓸 이벤트는 이름(event_type)을 통일**해 주세요.

| 우선 | 이벤트 | 지금 | 원하는 것 |
|------|--------|------|-----------|
| P0 | 온보딩 **단계별** 진행/이탈 | 거의 없음 | step 번호, 다음/닫기 |
| P0 | 초대 **링크 복사** | 없음 | 어느 그룹 링크인지 |
| P0 | 집중 **리포트/대시보드 조회** | 없음 | 어떤 화면 봤는지 |
| P1 | 의미 있는 **페이지 이동** | GA pageview만 | path (퍼널용) |
| P1 | 타이머 중 **이탈 시도** | 없음 | 어디서 막혔는지 |

**완료 기준**
- [ ] P0 이벤트가 합의된 방식(공통 API 또는 임시 GA)으로 찍힘
- [ ] event 이름 목록을 Notion/시트와 동일하게 맞춤

---

### 🆕 요청 F2. GA가 production에서 제대로 도는지 확인

**원하는 바**  
“GA 기본 지표를 대시보드에 넣는다”는 전제로,  
**지금 production에서 GA 측정이 켜져 있고**, 신규/활성 등이 콘솔에 쌓이는지 확인해 주세요.

**완료 기준**
- [ ] 측정 ID / Property 정보 공유
- [ ] “콘솔에서 최근 신규 사용자 보인다 / 안 보인다” 회신

---

`track('POKE_RESPOND', { action: 'accept' })` 같은 **공통 함수** 하나로 보내 주세요.

**완료 기준**

## 4. FE / BE 역할 정리 (오해 없게)

| | FE | BE |
|--|----|----|
| 역할 | **언제** 유저가 그걸 했는지 보냄 | **어디에** 남길지, API·테이블 |
| 예 | 온보딩 3단계 클릭, 링크 복사 | poke 발송 insert, activity_logs API |
| 이번 요청 | F1, F2, F3 | B1, B2, B3 |

같이 있어야 하는 것:  
> “분석 로그는 **공통 저장소 하나**로 모은다”는 원칙에 동의하는지.

## 5. 이번에 하지 않아도 되는 것 (범위 밖)

- 대시보드 HTML 디자인 (PM)
- 파이프라인이 DB 스냅샷 긁는 것 (이미 동작, 확장만 이어감)
- Looker / Metabase 도입 (나중에)
- Clarity 연동

## 6. 앞으로 요청하는 방식 (동의하면)

1. PM이 **Notion**에 “이벤트 추가” 카드만 올림 (`docs/Notion_로그요청_DB.md`)
2. FE/BE는 그 보드만 보고 구현
3. 상태가 `로그 심김`이면 PM이 파이프라인·대시보드·시트 반영

**요약:**  
지금은 GA 일부 + 기능 DB만 있고, **분석용 공통 로그·이력·GA↔대시보드 연동은 없다.**
