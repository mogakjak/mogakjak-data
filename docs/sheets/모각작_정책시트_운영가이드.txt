모각작 정책 시트 운영 가이드 (AS-IS / TO-BE / 최종 반영)

■ 추천: 하이브리드 (시트 분리 + 메인 시트에 상태 컬럼 최소 추가)

[시트 1] 모각작 서비스 정책 관리 (gid=0) — "현재 서비스 진실(AS-IS)"
  - 역할: PM/개발/QA가 "지금 뭐가 맞는지" 보는 단일 소스
  - 컬럼: 대분류 | 중분류 | 내용(쉬운) | 내용(코드) | 구현 여부 | 출처 | 중복정책 | 비고
  - TO-BE 문구는 여기에 넣지 않음 (혼선 방지)

[시트 2] 정책 변경안 (AS-IS / TO-BE) — "검토·개발 백로그" (에픽 묶음형)
  - 파일: 모각작_정책변경안_AS-IS_TO-BE.csv (데이터만)
  - 붙여넣기: 모각작_정책변경안_AS-IS_TO-BE_붙여넣기.csv
  - 컬럼: 변경ID | 상위ID | 유형 | 관련정책ID | 대분류 | 중분류 | AS-IS | TO-BE | 설명 | 구현(현재) | 구현(목표) | 출처/위치 | 우선순위 | 상태 | 비고
  - 유형: 변경 / 영향·유지 / 영향·수정 / 참고(구현)
  - 구조: 본 변경(상위ID 빈칸) 바로 아래에 영향 행(상위ID=본 변경ID). "영향 분석" 섹션 없음
  - 재생성: python gen_change_sheet_epic.py

[시트 3] 영역별 보조 (선택) — 홈 / 멤버카드 / 공식라운지
  - gid=0에 넣기엔 길어지는 상세를 분리
  - gid=0에는 "홈-xxx" 대분류로 요약 행 + "상세는 시트3" 링크

■ gid=0에 컬럼만 추가하는 방식 vs 시트 분리

| 방식 | 장점 | 단점 |
|------|------|------|
| 컬럼 추가 (AS-IS/TO-BE/상태) | 한 화면에서 비교 | 행이 길어짐·붙여넣기 깨짐·"현재"와 "예정" 혼재 |
| 시트 분리 (추천) | AS-IS 안정·TO-BE 실험 자유·변경 이력(변경ID) | 시트 간 동기화 필요 |

■ 최종 반영 워크플로

1. 기획: 시트2에 CHG-xxx 등록 (상태=검토중)
2. 개발: 상태=개발중, PR에 변경ID 명시
3. QA: 시트1(현재)과 빌드 동작 대조
4. 릴리스: 시트2 상태=완료 → 시트1 해당 행 내용·구현여부 갱신 → 시트2 행은 "완료"로 보관(이력)
5. 폐기: 시트2 상태=폐기, 시트1 미변경

■ gid=0에 최소로 추가할 컬럼 (선택)
  - "변경ID": CHG-001 등 연결 (비어 있으면 안정)
  - "최종수정일": YYYY-MM-DD

■ 구현 여부 4라벨 (고정)
  - 구현됨(FE+BE) / 구현됨(FE) / 구현됨(BE) / 데이터만(DB)
  - 빈칸 = 기능 없음
